## Interfaz o contrato

- Tipos principales:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
  pub enum CommandPayload {
      SetTaxRate { province: u32, new_rate: u32 },
      MoveArmy { army_id: u32, target_location: u32 },
      DeclareWar { target_entity: u32, cb: u16 },
      // Otros comandos iniciales mínimos
  }

  #[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
  pub struct Command {
      pub tick: u32,
      pub issuer: u32, // ID de jugador o país
      pub sequence: u32,
      pub payload: CommandPayload,
  }

  #[derive(Default, Serialize, Deserialize)]
  pub struct CommandLog {
      entries: Vec<Command>,
  }
  ```
- Bus de comandos: canal concurrente para que el cliente y los planificadores de IA encolen comandos con su marca de tick.
- Regla de la IA: los comandos emitidos por la IA en el día *d* se registran obligatoriamente con tick = *d + 1*.
- Ordenación canónica: los comandos de un tick se ordenan de forma determinista por `(tick, issuer, sequence)` antes de validarse.

## Criterios de aceptación

- [ ] Los comandos recibidos en un tick se ordenan de manera determinista e idéntica sin importar el orden de recepción en memoria.
- [ ] Serialización y deserialización completa del diario `CommandLog` con Serde (usando formato `postcard`).
- [ ] API para consultar y validar comandos aplicables a un tick determinado.

## Pruebas requeridas

- [ ] Prueba de concurrencia: múltiples hilos enviando comandos simultáneamente al bus y verificación de que el orden final tras la ordenación es estrictamente idéntico y determinista.
- [ ] Prueba de ida y vuelta de serialización del `CommandLog`.
