## Objetivo

Configurar el flujo de integración continua en `.github/workflows/ci.yml` para validar automáticamente cada pull request y push mediante `cargo xtask check`.

## Rol

role:infra

## Contexto

- Sección del documento maestro: §22 (Integración continua), §40 (Estructura del repositorio), §43 (Ciclo de vida de una tarea), Anexo P (Fase 0 · Preproducción), Anexo AF (Semana 1)
- ADR relacionados: ADR 0001
- Tareas relacionadas: #T-002, #T-003

## Archivos permitidos

- `.github/workflows/ci.yml`

## Interfaz o contrato

- Eventos disparadores: `pull_request` contra rama `main` y `push` directo en rama `main`.
- Entorno de ejecución: `ubuntu-latest` (y matriz adicional si se define).
- Pasos del pipeline:
  1. `actions/checkout@v4`
  2. Instalación de la versión exacta de Rust fijada en `rust-toolchain.toml` con componentes `rustfmt` y `clippy`.
  3. Gestión de caché (`Swatinem/rust-cache` o `actions/cache`) para el directorio de Cargo y `target/`.
  4. Ejecución del comando de validación del repositorio: `cargo xtask check`.

## Criterios de aceptación

- [ ] Archivo de flujo `.github/workflows/ci.yml` con sintaxis válida de GitHub Actions.
- [ ] Ejecuta `cargo xtask check` sin requerir scripts no autorizados ni dependencias de red indebidas en los tests.
- [ ] La caché de dependencias reduce los tiempos de compilación subsecuentes.
- [ ] El flujo finaliza en verde en un pull request de prueba.

## Pruebas requeridas

- [ ] Validación sintáctica del archivo YAML.
- [ ] Comprobación del paso de CI en pull request de prueba sin errores de entorno.

## Fuera de alcance

- Flujo de campañas masivas nocturnas (`nightly-lab.yml`).
- Tareas de despliegue o publicación web en `website/`.

## Estimación

2 a 3 horas de agente.
