## Objetivo

Implementar en `crates/e101-sim` la fase de aplicación de deltas (`apply.rs`) con clave de ordenación canónica para asegurar transiciones de estado deterministas e independientes de la concurrencia.

## Interfaz o contrato

- Tipos fundamentales:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord)]
  pub struct DeltaKey {
      pub phase: u8,
      pub target_entity: u32,
      pub field_id: u16,
      pub sequence: u32,
  }

  pub struct Delta {
      pub key: DeltaKey,
      pub mutation: MutationOp,
  }

  pub struct Deltas {
      buffer: Vec<Delta>,
  }
  ```
- Firma estándar de sistemas de simulación: `fn run(state: &State, deltas: &mut Deltas);`.
- Fase de aplicación:
  ```rust
  pub fn apply_deltas(state: &mut State, deltas: &mut [Delta]) -> Result<(), InvariantError>;
  ```
  1. Ordena el búfer de deltas por `DeltaKey` canónica (`sort_unstable_by_key`).
  2. Aplica de manera secuencial y determinista las mutaciones sobre `State`.
  3. Ejecuta la validación de invariantes en modo de prueba (`cfg(debug_assertions)` o flag de testing).

## Criterios de aceptación

- [ ] La fase de lectura paralela (`&State`) garantiza cero mutaciones concurrentes en el estado global.
- [ ] La fase de aplicación produce un estado bit a bit idéntico tanto si los deltas fueron calculados por 1 hilo como por 16 hilos en paralelo.
- [ ] Si un delta viola un invariante registrado (e.g. balance contable negativo, territorio huérfano), se aborta con error detallado.

## Pruebas requeridas

- [ ] Prueba multihilo con `rayon`: generar 10.000 deltas distribuidos en varios hilos y verificar que `apply_deltas` produce exactamente el mismo resultado final bit a bit que en ejecución monotarea.
- [ ] Prueba de invariantes: inyectar un delta inválido y comprobar la captura del error correspondiente.
