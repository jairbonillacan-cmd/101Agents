## Objetivo

Desarrollar el Spike G de cliente: integración del renderizado de mapa nativo en wgpu con interfaz de usuario en HTML/CSS embebida dentro de una vista web.

## Rol

role:client

## Contexto

- Sección del documento maestro: §22 (Opciones para el cliente - Opción G wgpu + UI web, Plan del spike de selección), Anexo P (Fase 1 · Núcleo)
- ADR relacionados: ADR 0004
- Tareas relacionadas: #T-117, #T-118, #T-120

## Archivos permitidos

- Rama de spike `spike/client-g-web-ui`
- `spikes/web-ui/**`

## Interfaz o contrato

- Stack técnico: Rust + `wgpu` + vista web embebida (ej. `wry` o similar) como capa superpuesta transparente.
- Renderizado de mapa en el fondo nativo con la textura de IDs de ~400 provincias de T-117.
- Capa de interfaz web:
  - HTML/CSS y TypeScript/JS mínimo ejecutado en la vista web.
  - Panel de provincia denso con tabla de 60 filas ordenables y tooltips anidados de tres niveles de profundidad conectados a datos simulados.
- Puente de comunicación IPC:
  - Protocolo ligero bidireccional mediante mensajes JSON o binarios entre la vista web y el hilo nativo de Rust.

## Criterios de aceptación

- [ ] Renderizado coordinado de mapa nativo a 60 FPS con panel web interactivo sobreimpreso.
- [ ] Tooltip anidado de 3 niveles con apertura ágil e inspección fluida sin stuttering visual.
- [ ] Medición cuantitativa de métricas: consumo de memoria RAM (debido al motor web), latencia IPC entre Rust y JS, y facilidad de estilar con CSS.
- [ ] Documentación clara de la complejidad de composición entre la ventana nativa y la vista web.

## Pruebas requeridas

- [ ] Medición de impacto en FPS de la vista web durante interacciones intensivas (scroll rápido de tablas y apertura de tooltips).
- [ ] Verificación de funcionamiento consistente en Windows (WebView2).

## Fuera de alcance

- Navegador web con acceso a internet exterior o llamadas de red remotas.

## Estimación

4 a 6 horas de agente.
