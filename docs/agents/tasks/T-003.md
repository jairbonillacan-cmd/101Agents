## Objetivo

Implementar el crate interno `tools/xtask` con el subcomando `check` para ejecutar formato, lints de clippy y pruebas en todo el workspace.

## Rol

role:infra

## Contexto

- Sección del documento maestro: §40 (Estructura del repositorio), §45 (Automatización con cargo xtask), §46 (Reglas de código), Anexo P (Fase 0 · Preproducción), Anexo AF (Semana 1)
- ADR relacionados: ADR 0001, ADR 0002
- Tareas relacionadas: #T-002, #T-004, #T-106, #T-107

## Archivos permitidos

- `tools/xtask/**`

## Interfaz o contrato

- Invocación desde la raíz del repositorio: `cargo xtask <subcomando>`.
- Subcomando obligatorio: `cargo xtask check`.
- Secuencia interna de verificación en `check`:
  1. `cargo fmt --all -- --check`
  2. `cargo clippy --workspace --all-targets -- -D warnings`
  3. `cargo test --workspace`
- Código de salida: 0 si todas las fases tienen éxito; código distinto de 0 en el primer fallo con mensaje explicativo.

## Criterios de aceptación

- [ ] Crate binario `tools/xtask` compila sin advertencias dentro del workspace.
- [ ] `cargo xtask check` se ejecuta correctamente en local.
- [ ] Si `cargo fmt` o `cargo clippy` detectan problemas, el subcomando aborta con código de error claro.
- [ ] Muestra ayuda legible ante `cargo xtask --help`.

## Pruebas requeridas

- [ ] Ejecutar `cargo xtask check` en el workspace y verificar código de salida 0.
- [ ] Introducir un fallo de formato simulado y verificar que `cargo xtask check` termina con código de error.

## Fuera de alcance

- Subcomandos de determinismo (`golden`), datos (`data`), laboratorio (`lab`) o benchmarks (`bench`), a implementar en fases posteriores.
