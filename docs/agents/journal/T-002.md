## Decisiones

| Decisión | Motivo | Alternativas descartadas |
| --- | --- | --- |
| Canal fijado `1.99.1` en `rust-toolchain.toml` (no "stable") | Versiones reproducibles para agentes y CI; es la estable concreta instalada en local (verificado con `rustup run 1.99.1 rustc --version`) | "stable" a secas (deriva entre máquinas); nightly (innecesario) |
| `[workspace.dependencies]` con versiones exactas consultadas en la API de crates.io (2026-10-24) | Fijar por adelantado el grafo que usarán los crates `e101-*` sin volver a tocar el manifiesto raíz | Declararlas sobre la marcha en cada crate (deriva de versiones) |
| xtask sin dependencias externas (solo `std`) | Compilación rápida y superficie de supply-chain mínima para la herramienta que audita todo lo demás | clap/xshell (más cómodos, más riesgo) |
| `check` ejecuta fmt, clippy `-D warnings`, `test --workspace` y `cargo deny check`; antes sondea `cargo-deny --version` y si no existe falla con aviso de instalación | Espejo exacto de AGENTS.md §6; el aviso evita falsos verdes | Continuar sin cargo-deny (verde engañoso) |
| Stubs con ID de tarea: golden→T-111, data→T-202, lab→T-216; bench y docs→"T-XXX (sin asignar)" | El Anexo P no tiene tareas específicas para bench ni docs; se usa el ID de la tarea que traerá cada subcomando y "sin asignar" donde no existe | Inventar IDs inexistentes |
| `deny.toml` formato v2 sin `version` en `[bans]` y `[sources]` | cargo-deny 0.20.2 lo rechaza (solo licenses/advisories admiten `version = 2`); validado ejecutando `cargo deny check` | Mantener el campo (falla el parseo) |
| MPL-2.0 fuera de `allow`, documentada como bloque `exceptions` comentado | Copyleft por archivo: solo se admitiría crate a crate como excepción documentada | Meterla en `allow` global |
| CI: lista de paths duplicada en `pull_request` y `push` | GitHub Actions no admite anclas YAML | Anclas YAML (no soportadas) |
| CI: rust-cache con `cache-directories: ~/.cargo/bin` + `cargo install cargo-deny --locked` | Repo público: minimizar minutos; el binario queda cacheado entre ejecuciones | Acción Docker de cargo-deny (no deja el binario en el runner para que `cargo xtask check` lo invoque) |
| Commits creados con índice temporal (`git write-tree` + `git commit-tree`) sin cambiar de rama | El árbol de trabajo compartido estaba en la rama de otro agente en paralelo; así no se revierte su trabajo ni se toca su HEAD | `git switch` (cambiaría el HEAD bajo el otro agente) |

## Problemas encontrados

- Al empezar, el árbol no estaba limpio: cambios sin confirmar en `website/` y un archivo no rastreado en `docs/agents/ORCHESTRATOR_PROMPTS.md`, de otros agentes en paralelo. No se tocaron; esta tarea solo crea archivos propios en sus rutas permitidas.
- A mitad de la tarea, otro agente en paralelo cambió la rama activa del repositorio compartido a `agent/docs/D1-style-tasks-labels`. Resuelto commiteando en la rama propia con `git commit-tree` e índice temporal, sin tocar HEAD ni el árbol del otro agente.
- `cargo deny check` emite avisos informativos `license-not-encountered` mientras el workspace no tenga dependencias externas en el grafo (las declaradas en `[workspace.dependencies]` aún no las usa ningún crate). No son errores; desaparecerán cuando lleguen los crates `e101-*`.
- `rustup toolchain install` (sin argumentos, lee `rust-toolchain.toml`) requiere rustup moderno; los runners de GitHub lo cumplen. Si algún entorno local tuviera rustup antiguo, instalar la 1.99.1 a mano.
